# 提交前门禁（pre-commit hook）

`.githooks/pre-commit` 在每次 `git commit` 落库前跑两个既有测试套件，任一失败就**阻止提交**：

| 套件 | 拦什么 |
| --- | --- |
| `repo/source/local-service/test/repo-privacy.test.js` | 被提交的文件里出现作者本机私有路径 / Windows 用户名 / token 片段 |
| `repo/source/local-service/test/version-sync.test.js` | 6 处版本号不一致、`package.json` / `package-lock.json` 损坏或版本漂移 |

背景：1.0.4 发布后公开仓库里漏出过作者本机路径（`AGENTS.md` 被推上公开仓库那次），打包侧早有
`release-privacy.test.js` 守产物，但**源码与文档侧没有门禁**，所以漏出去了。门禁放在 commit 这一步，
比等测试失败或事后审计更早。

## 启用（每台机器一次）

```sh
git config core.hooksPath .githooks
```

这是写进本机 `.git/config` 的本地配置，**不随版本库分发** —— 克隆仓库后要自己启用一次。
`core.hooksPath` 指向版本库里的相对路径，钩子脚本本身是版本化的，团队改门禁等于改代码，有人 review。

关闭：

```sh
git config --unset core.hooksPath
```

## 验证已启用

```sh
git config core.hooksPath        # 应输出 .githooks
```

再随便做一次提交，成功时能看到一行：

```
[提交前门禁] ✓ 隐私与版本检查通过（repo-privacy + version-sync）
```

失败时会打印被拦下的**命中行**（`文件:行 命中「…」:: 原文`）、测试输出末 25 行，以及完整日志路径。

## 一键自证

`.githooks/verify-hook.ps1` 在系统临时目录造一个**副本仓库**（不碰当前仓库），真实跑一遍门禁并检查它是否真的拦得住：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .githooks\verify-hook.ps1
```

- **第 1 段（任何环境都能跑）**：直接跑门禁用的两个套件，看三种仓库状态的退出码并打印被拦下的命中行 ——
  干净 → `0`、含本机私有路径的文件 → `1`、版本漂移 → `1`。
- **第 2 段（需要能执行 POSIX sh 的环境）**：真实跑 `git commit` ——
  A 干净提交通过、B 含私有路径的提交被拒、C 版本漂移的提交被拒、D `git checkout` 之后 hook 仍是 LF。

> 受限沙箱（如 DSH）里 msys 的 `sh.exe` 起不来（`fatal error - couldn't create signal pipe, Win32 error 5`），
> git 的 hook 机制整体不可用 —— 一个只写 `exit 0` 的空白 hook 在那里同样跑不起来。
> 这时第 2 段会自动 `[SKIP]` 并说明原因，只拿第 1 段的证据；完整自证请在普通终端里重跑本脚本。

## 失败怎么修

- **隐私命中**：按提示脱敏 —— 盘符统一写 `X:\` 或 `C:\`，临时目录用 `os.tmpdir()`，
  相对位置用相对路径，用户名 / token 片段用字符串拼接写（`"ghp" + "_"`）。
  具体禁止清单与拼接写法见 `repo/source/local-service/test/repo-privacy.test.js` 顶部注释。
- **版本漂移**：用一键工具同步，别手改：
  `repo/source/tools/bump-version.ps1 -Check`（只报不改）→ `-Version <新版本>`（写盘并逐处打印）。
- **测试文件缺失**：门禁会因为「跑不了」而失败 —— 删测试不是绕过门禁的办法。

## 确实要绕过

```sh
git commit --no-verify
```

只在确认门禁误报时用，并在提交说明里写清原因。绕过是显式行为，日志里能看到；`--no-verify`
不会让 `core.hooksPath` 失效，下次提交照样跑门禁。

## 实现约束（改 hook 前先读）

- **保持 LF 行尾**：`pre-commit` 是 `#!/bin/sh` 脚本，CRLF 会让 shebang 变成 `/bin/sh^M`，
  git 执行 hook 直接报 `bad interpreter`。`.githooks/.gitattributes` 里的 `* text eol=lf`
  就是为此存在的（仓库根是 `* text=auto`，本机 `core.autocrlf=true` 会转成 CRLF）。
- **不用管道 / 命令替换取子进程输出**：受限沙箱里 `child_process` 的 `stdio: "pipe"` 会 EPERM，
  文件重定向（`> file 2>&1` + 读文件）才行。hook 内部因此一律用文件 fd，连 `$(...)` 都避开；
  `repo-privacy.test.js` 取 `git ls-files` 用的是同一招。
- **必须带 `--experimental-test-isolation=none`**（node ≥ 22）：受限沙箱下不带这个旗标跑不了
  `node --test`。老版本 node 不认识该旗标，hook 会按主版本号自动降级。
- **缺 node 就拦住提交**，不是静默放过（提示里给安装方式与跳过方式）。
- **Windows 上不需要执行位**：`core.fileMode=false`，git 用自带的 sh 执行 hook。
  在 Linux / macOS 上克隆后若报权限问题，补一次 `chmod +x .githooks/pre-commit`。
- **耗时**：两个套件合并成一次 `node --test` 调用，实测约 0.5 秒量级，不值得为省时间削减检查范围。
