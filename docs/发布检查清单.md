# 发布检查清单（维护者）

## 发布前必做

- [ ] `midi/community-catalog.js` 里的 `CATALOG_URL` 改成你自己的仓库：
      `https://raw.githubusercontent.com/<你的账号>/<仓库名>/main/data/catalog.json`
- [ ] 跑门禁：`node tools/sanitize.js check data/catalog.json`
- [ ] 确认仓库里没有任何个人数据：
      `git status` 里不应出现 `记录/`、`备份/`、`*.sqlite`、`*.mp3`、`*.mp4`、`*queue.json`
      （`.gitignore` 已经排除这些，提交前仍要瞄一眼）
- [ ] 搜一遍泄漏关键词：`E:\`、`C:\Users`、你的用户名、`OliviaSoul\UserData`
- [ ] `隐私说明.md` 与实际行为一致（只传曲名 + 指纹）
- [ ] 试听台前的询问页文案与实际一致

## 打包

    cd source/local-service
    npm install
    npm run build:win

- 需要 .NET SDK（编译 C# WebView2 宿主）
- 出**安装包**还需要 Inno Setup；只出可运行目录不需要
- 上游脚本要求版本号固定为 `2008.2.7`（林离生日），改动版本号会导致脚本报错

## 合并社区投稿

    node tools/sanitize.js check data/community/<某人>.json   # 先校验
    node tools/merge-inbox.js                                 # 合并 + 按指纹去重
    node tools/merge-inbox.js --dry-run                       # 只看报告

报告里会出现三类：
- **新增** —— 直接进名单
- **指纹判定重复** —— 与已有条目是同一首歌，自动合并
- **需人工核对** —— 指纹相同但名字不同（原曲/翻奏？），**不要自动合并**，听过再定

## 打包前自审清单（每次打包必须逐条过，不许跳）

这套清单是被真实事故逼出来的，每一条都对应一次线上故障：

| # | 检查 | 怎么查 | 对应的历史事故 |
| --- | --- | --- | --- |
| 1 | **所有新增模块都在打包清单里** | `node tools\检查打包清单.mjs <打包输出>` | `logs.js` 漏进包 → Node 启动即崩、界面显示"本地服务启动失败" |
| 2 | **新页面用到的每个元素都有样式** | 查 `listen-naming.css` 是否覆盖 `h2/h3/p/small/label/select/textarea/input/table/th/td/ul/li/pre` | 11 个 `ln-*` 类没有样式表 → 页面排版全是裸元素 |
| 3 | **新页面面板在 `.content` 内部** | 看 `index.html` 里新面板是否在 `</div>`（content 结束）之前 | 面板插到 `.content` 外面 → 侧边栏消失、内容不能滚 |
| 4 | **路由处理器对入参判空** | 搜 `url.pathname`，必须都是 `typeof url === "string" ? … : (url && url.pathname) || ""` 这种写法 | 未判空 → 整站 500、界面只显示一段 JSON |
| 5 | **模块初始化不缓存"空状态"** | 挂载处搜 `??=`，凡是依赖运行时设置的都要能重建 | 启动瞬间把空曲库路径缓存死 → 之后设好也不生效 |
| 6 | **未配置时要有明确提示** | 走一遍"没设曲库/没设反馈仓库"的分支，确认页面有提示而不是静默失败或显示"全部听完了" | 反馈按钮点不动、试听页误显示"全部听完了" |
| 7 | **页面不许横向溢出** | 打开每个新页面，确认不能左右拖动、右侧文字不被切 | 声明页能左右拖、右侧文字被切掉 |

**跑完这七条再执行打包命令** ✗ 顺序不能颠倒 ✓
