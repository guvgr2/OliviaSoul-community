OliviaSoul-community · 林离离线增强工具
软件版本：2008.2.7
更新标识：2008.2.7-linli9-1.0.6
本支从上游 OliviaSoul（linli 分支）分叉而来，在保留上游全部功能的基础上，增加了曲名与时段整理、时段依据复核、数据备份与恢复、导出/导入换电脑、游戏崩溃记录与日志、游戏崩溃规避开关、功能地图引导等本地功能。凡本支新增的条目，正文中都标有“本支新增”。上游出处与许可见文末“出处与致谢”。
本次提供完整 Setup.exe 与 Portable.zip，包含上游全部已合并更新。升级后请更新客户端补丁至 FE v60 / WebPlayer v19（本版补丁内容有变化，务必更新一次；下文历史段落里出现的 v59 是对应当时版本的要求，本版补丁为 v60）。下载、校验值与更新说明以本支发布页 https://github.com/guvgr2/OliviaSoul-community/releases 为准。

一、安装与升级
1. 需要 Windows x64 和用户自行安装的《BSide: Olivia Lin》离线客户端。
2. 推荐运行 OliviaSoul-2008.2.7-linli9-1.0.6-Setup.exe；安装版默认安装到 %LOCALAPPDATA%\Programs\OliviaSoul，也可以选择游戏目录之外、非盘符根目录的独立可写目录。便携版请完整解压 OliviaSoul-2008.2.7-linli9-1.0.6-Portable.zip 后运行 OliviaSoul.exe，不要直接在压缩包里打开。
3. 升级时运行新版安装包并选择原安装目录覆盖安装，无需先卸载旧版。不要同时运行安装版和便携版。用户无需另装 Node.js、npm、Python 或 MIDI 渲染工具。
4. 升级前先关闭游戏，从托盘完全退出 OliviaSoul，备份安装目录下整个 UserData，再在同一目录更新。升级会保留 UserData，因此管理页会继续显示你自己保存过的模型、接口和最后有效曲目位置；这不表示安装包携带了维护者数据。
5. 缺少 Microsoft Edge WebView2 Runtime 时，首次启动会尝试运行微软安装引导，可能需要联网。失败时记录错误，检查系统运行时，不要反复强制重启电脑。
6. 公开包不含游戏、官方视频、账号、个人数据、真实模型名、私人接口、磁盘路径或已配置的 API Key。全新安装会使用通用占位配置；首次使用看到未配置模型、空信箱或空作品库是正常的。
7. 本次更新标识为 2008.2.7-linli9-1.0.6，程序版本仍为 2008.2.7。本包包含上游 linli.9 的全部功能（桌面歌词、播放控制、曲库导入与移除、通用兼容 API 等），并在此基础上加入本支新增功能：可选模型（DeepSeek / 智谱 GLM / Kimi 月之暗面，默认 deepseek-flash）、时段依据复核、数据备份与恢复、导出/导入、游戏崩溃记录与日志、游戏崩溃规避（实验性，实测对本游戏无效）、功能地图。本版还降低了常驻轮询频率（播放器 1 秒→3 秒、「我的上传」列表 5 秒→30 秒且后台跳过、服务端存储状态 2 秒→10 秒），游戏侧与后台的请求量都明显减少。客户端补丁为 FE v59 / WebPlayer v19，低于该版本时请在「客户端与桌面」更新。本版还让「更新客户端补丁」在找不到原版备份时自动去同机其它 OliviaSoul 安装里找一份（面板会写明来源），换目录或换便携包之后不必再手工复制备份。另外：「高级设置 → 诊断」有「一键体检」（实验性，看内存/内核内存池/常驻进程与崩溃概览，只在本机显示、不上传）；更新客户端补丁后会自检，不过会自动还原；模型「保存并测试」失败时会给出该查哪儿的结论。

【本版新增 · 1.0.6 一项修复（更新检查误报）】
1. 更新检查不再把最新版误报成有新版本（本版修复）：GitHub 上的 Release 标签形如 v2008.2.7-linli9-1.0.5，前面带一个 v，而程序里的版本号不带 v。旧版比较时遇到带 v 的标签会解析失败、退回按文字比较，于是这两个被当成两个不同的版本 —— 装的已经是最新版，「软件更新」页却一直显示「发现新版本，可以下载」。更麻烦的是同一个判断还守着下载入口，点「下载并安装更新」会真的重新下载并安装约 602 MB 的同一个版本，而不是提示「当前已经是最新版本」。本版在比较前先剥掉标签开头那一个 v 或 V（只剥紧跟数字的那一个字符，verify- 这类文字不受影响），两边都解析不出来时的兜底比较也同样先剥。顺带修正一处相关文案：结果行原先在前端自己比「当前版本」与「GitHub 最新版本」的文字，即使后端修好也会显示成「当前版本高于 GitHub 公开版」，现在改由后端给出结论、前端只读它。本版未改客户端补丁（仍为 FE v60 / WebPlayer v19），不需要重打补丁。

【本版新增 · 1.0.5 三项改动（补丁失效即时提醒 / 周期自动备份 / 版本号与发布工具）】
1. 补丁失效即时提醒（本支新增）：Steam 校验文件或官方更新游戏会把界面补丁（feapp.dat）与播放器补丁（webplayer.dat）覆盖回原版，补丁就没了。以前界面上只有「客户端与桌面」页签上的角标，用户没有理由去点它，于是「游戏连不上本机服务」也查不出原因。本版在每次状态刷新后与「上次已知的挂载状态」对比（记在本机存储里，重启程序依然有效）：只有「上次确实挂着、这次没了」才提醒一次，弹出「游戏补丁已失效」，写明是哪一边的补丁没了、后果是什么（界面补丁不显示、歌词与续播不生效），点「去重打补丁」直接切到「客户端与桌面」页，再点那里的「启用本地服务」（若显示为「重打补丁（同步端口）」也一样）把补丁写回游戏即可；选「稍后再说」则本次不再打扰。首次安装、状态没变化都不会提醒；提醒本身失败只写日志，不阻塞启动与服务就绪。
2. 周期自动备份（本支新增）：「高级设置 → 诊断 → 数据备份与恢复」新增一行「周期自动备份」，可选「关闭 / 每 1 天（默认）/ 每 7 天」。程序启动时检查距上次备份的时间，超过间隔就自动留一份，只保留最近 7 份；手动备份与升级前备份不会被清理。就算你从不点「立即备份」，也不会一直没有退路。备份失败只记日志、不影响使用。
3. 版本号一键同步与一键发布（维护者工具，不影响使用者）：仓库里新增 repo\source\tools\bump-version.ps1（一条命令把发版各处的版本号一起改到同一版，加 -Check 只报不改，用于核对是否漂移）与 repo\source\tools\publish.ps1（一键发布：默认 dry-run 只打印将要执行的步骤、零副作用，加 -Execute 才真跑门禁、收产物与 SHA256、建 GitHub Release 并核对结果），另有 git 提交前门禁 .githooks/pre-commit（提交前自动跑隐私与版本一致性两个套件，防止本机私有路径或版本漂移被提交）。这些都是维护者用的脚本，普通用户照常覆盖安装即可。

【本版新增 · 1.0.4 三项改动（回退补丁 / 再次播放不再跳列表第一首 / 更新通道）】
1. 「回退补丁（还原原版）」按钮（本支新增）：补丁打歪导致游戏白屏、连不上时，到「客户端与桌面」页，状态徽章下方会出现「补丁出问题？」提示与「回退补丁（还原原版）」按钮（只在游戏目录里确实存在本机补丁时出现：已挂载、部分挂载、补丁待更新都算）。点它 → 二次确认 → 程序用**既有的还原链路**把 feapp / webplayer 还原成本机备份里的原版（补丁前状态），完成后自动复查状态、徽章变回「服务未挂载」。**不会丢存档**：存档在 UserData 里，回退只写游戏安装目录里的补丁文件；回退后可随时点「启用本地服务」重新打补丁。注意：它与日常用的「停用服务」不是两个不同的还原动作 —— 「停用服务」走的是同一条还原链路，同样会写游戏文件；日常启停照旧用「停用服务」，只有补丁把游戏搞坏时才用「回退补丁（还原原版）」（标签与说明已写明区别）。失败时会给出原因与分类编号（如 BACKUP_INVALID / GAME_RUNNING / PATH_INVALID），请先保留 UserData 与备份，再按提示联系支持。
2. 「我的上传」停止或结束后再次播放不再跳回列表第一首（本版修复，**需客户端补丁 FE v60**）：以前停止播放后再点播放，会跳到「我的上传」列表里的第一首；现在会接着播你刚才点过的那一首。根因是原生在「当前曲」被清空后回落到「播列表第一首」，而 v59 及更早的补丁按 id 去当前列表里找本地作品必然落空，所以这个问题在 v59 上一直存在。请到「客户端与桌面」→「更新客户端补丁」，把补丁更新到 **FE v60 或更高**。失败隔离：这段逻辑整体包在自己的 try/catch 里，最坏结果只是「这一次点击不播」—— 不包装 playSong、不碰播放会话，不会播错歌、不会黑屏。
3. stable / beta 双通道更新（本支新增）：到「软件更新」页的「更新通道」下拉框选 **稳定版（只收正式 Release，默认）** 或 **测试版（含 prerelease，可能不稳定）**；下方会写明「当前通道」。通道存在本机设置里，切换后立即生效，不用重启程序或服务。选测试版后，检查更新会读 GitHub 的 Release 列表并接受被勾成 prerelease 的测试版；下载也按通道取包（beta 通道点「下载安装包」拿到的就是测试版）。**连不上更新服务时**（本机直连 github.com 的部分 IP 会被 SNI 阻断，这是常态而非异常），页面不再弹错误窗口、也不会转圈卡死，而是给出原因，并在下方显示「打开发布页」按钮与可复制的发布页链接，手动到发布页下载即可；此时**绝不会显示「已经是最新版本」**。服务端契约：检查更新失败一律返回 200 + 降级标记（degraded），不再返回 502。

【本版修复 · 数据搬家后游戏看不到曲目 / 满屏 malformed】搬家会把主库换成真实那份，但旧的 -shm/-wal 删不掉（程序正打开着它们），而清理只在程序启动时执行 —— 于是搬家后服务会一直报 database disk image is malformed；游戏此时加载「我的上传」会拿到空白且不会自动重试，必须手动重启程序与游戏。本版改为：搬家成功后自动重启本地服务、运行中连续损坏时自动重启自愈，并把「真实读探测」恢复为读业务表。现在搬家后不需要手动重启。（排查时可用环境变量 OLIVIA_DISABLE_AUTO_RESTART=1 关闭自动重启。）

【本版新增 · 暂停续播（实验性）】游戏 UI 的「暂停」实际发送 stop（游戏原生 JS 里没有 pause/resume 命令），服务端因此结束会话、清空进度，「继续」只能从头播。本版记住播放位置：同一首在 30 分钟内再次播放会从上次位置接着播（换歌或超 30 分钟则从头）。这是实验性功能，只影响「从哪里开始播」，即使完全失效也不影响播放、切歌、曲库等其他功能。

【已更新 · 背景音让位（重做并亲测通过）】播放「我的上传」里自己导入的曲子时，游戏背景音现在会让位：本地播放开始时挂起游戏的氛围音、结束时恢复。做法与更早的两次尝试（改播放来源标记、包装播放函数）完全不同 —— 这次调用的是游戏**自己的氛围音接口**（ambientSound 的 acquireExclusive / releaseExclusive），完全不碰播放路径，所以不会出现游戏黑屏；取不到该接口时静默跳过，最坏结果只是不让位，不影响播放。暂停或停止播放约 2.5 秒后背景音恢复；在本地作品之间切歌不会闪出背景音。该实现需要客户端补丁 **FE v59 或更高**（旧补丁里没有这段代码）。

【本版修复 · 「启用本地服务」报 backup feapp archive identity mismatch】若你已给游戏打过补丁、程序却显示「服务未挂载」，点「启用本地服务」可能报这个错 —— 而游戏文件和原版备份其实都完好。原因是我们自己的备份身份校验有缺陷（上游没有这层校验，所以从不报错）：补丁会改 main 与 zh-cn 两个文件，而放行文本差异的「已知补丁版本」列表停在 v45，补丁升到 v46 后认不出来；该判定还额外要求「已挂载」，可「未挂载」恰恰是最需要备份的状态。本版已修：列表补上 v46，判定不再依赖挂载状态。

【本版紧急修复 · g24 导致全新安装起不来】若你在 g24 上遇到「本地服务启动失败 / Node 服务已退出，退出码 1」，日志里是 no such table: user_songs —— 那是 g24 引入的回归：它的数据库探测查询了 user_songs，而该表由 MidiStore 稍后创建，全新安装时还不存在。本版已修：探测只读 sqlite_master（必然存在），且探测中的非损坏类错误一律忽略、绝不影响启动。只有 g24 一个版本受影响，数据没有损坏，升到本版即可。

【本版修复 · 数据库打不开（database disk image is malformed）】若程序曾出现「启动看着正常、过一会儿开始反复报 database disk image is malformed」，本版已修好：原来自愈只在打开数据库报错时才动手，而 SQLite 是惰性读取的（启动探测碰不到坏页），且实际形态常是「主库完好 + 陈旧的 -shm（-wal 为 0 字节）」。本版会在启动打开前主动移开这种明显不一致的伴随文件（保留 .broken-* 留档），并在打开后做一次真实读探测。只碰可重建的伴随文件、主库一个字节不改；-wal 里有真实内容时绝不动。

【本版优化 · 切歌更顺（实验性）】不少本地作品的 MP4 把解码索引（moov）放在文件末尾，播放器必须先读到文件末尾才能开始解码，表现就是切歌卡几秒（而同一首重播很快）。本版在播放时优先使用「索引前置副本」（用随包 ffmpeg 无损重封装，不修改原始文件、也不写入你的曲库目录），缓存在程序数据目录的 .faststart-cache 下。第一次播放某首仍用原文件并在后台生成副本，之后播放即可秒开。收益与磁盘、播放器有关，属实验性改进。

【便携版换版必读】便携版每个新版解压出来都是全新的数据目录。换了新版之后如果游戏里还列着歌、一播就提示「官方演奏视频不存在」，那不是文件丢了，是数据没搬过来 —— 到「数据搬家」把旧安装的数据复制过来，再重启程序；游戏里若仍显示旧列表，重开一次游戏让它重新读取曲库。试听工具面板顶部在检测到这种情况时会直接给出提示。
8. 本包未配置代码签名，Windows 可能显示“未知发布者”。请核对来源和随包 SHA256SUMS.txt；不要关闭安全软件或使用来历不明的改包。
9. 新构建的安装向导支持简体中文和 English。首次按 Windows 显示语言选择默认语言（其他语言回退英文），开始安装时可以手动选择；升级默认沿用上次选择，仍可更改。卸载沿用安装语言。提供安装位置与桌面快捷方式选项。软件名、版本号、路径和错误代码保留原样；Windows 自身的权限/安全提示随系统语言显示。此选项不切换 OliviaSoul 管理界面语言。

13. 本支新增：覆盖安装新版本后首次启动时，程序会发现“版本变了”并自动备份一次升级前的旧数据库，位置在“高级设置 → 诊断 → 数据备份与恢复”。这是额外一层保险，不替代你自己备份整个 UserData。

管理页圆点提醒：选项卡右上角金色点表示新版本或已完成任务，打开对应选项卡后消失；红色点表示模型配置/连接、客户端状态或任务异常，查看不会消除，问题解决后才消失。悬停或辅助功能标签可查看原因。普通已读记录保存在当前浏览器/管理窗口配置中，清除浏览器数据或更换访问地址可能重新提示。页面加载时会静默检查一次公开版本，不会自动下载安装，也不会因为查看圆点额外请求 AI。

客户端检查：界面显示 FE/WP 版本和是否需要更新。重复的只读检查会合并，检查超时最多自动重试一次；写入补丁不会自动重试。若仍报超时/失败，请保留具体提示，不要连续点击或强制关机。

二、卸载与移除
1. 卸载前先完全退出游戏和 Steam，再从托盘退出 OliviaSoul。卸载器不会强行结束这些进程；仍在运行时会中止并提示用户处理。
2. 安装版可打开“Windows 设置 → 应用 → 已安装的应用”，找到 Olivia Soul 并选择“卸载”；也可以直接运行 <OliviaSoul安装目录>\unins000.exe。
3. 卸载器会在删除 OliviaSoul 前，安全恢复所有已登记且仍处于启用状态的 FE、WebPlayer、受支持的客户端 DLL 补丁及严格匹配的 Steam 启动项。恢复会先完整预检路径、备份、哈希和占用状态；不会恢复或修改 usersettings.dat。
4. 任一客户端路径失效、备份缺失/损坏、目标后来被用户或游戏更新修改、权限不足或 Steam 启动项不再匹配时，卸载都会中止，并保留 OliviaSoul、UserData、恢复工具和备份。按提示修复后重新运行卸载；不要直接删除安装目录。
5. 实际卸载之前仍应备份 <OliviaSoul安装目录>\UserData\ 和仍在使用的外部音乐目录。卸载不是备份；卸载器不会删除来源视频，也不会替用户迁移或整理安装目录外的音乐。
6. UserData 默认保留，以保护信件、设置、名称纠错记录和客户端恢复证据。确认备份完整且确实不再需要后，才由用户自行处理该目录；不要为测试“干净界面”而误删唯一数据。
7. 便携版没有 Windows 卸载器。请先在“客户端与桌面”逐个选择曾挂载的客户端并停用服务；如果使用过 Steam 启动衔接工具，再按随包说明恢复原启动项。全部确认恢复后才能移除整个便携版目录，不能只删 OliviaSoul.exe。
8. 普通升级建议直接运行新安装包并沿用原安装目录，不需要先卸载旧版。

三、先开后端，再进入游戏
1. 启动 OliviaSoul，等待管理窗口和本机服务就绪。
2. 首次连接或需要重新挂载时，先关闭游戏。
3. 打开“客户端与桌面”，点击“选择 exe”，选中自己游戏目录内正确的启动程序，确认端口（默认 27149），点击“启用服务”并等待成功。
4. 再从 Steam 启动游戏。使用信件、我的上传等本地功能时，保持 OliviaSoul 在后台运行。
5. 从 r9 升级后，请关闭游戏，在“客户端与桌面”重新启用服务，补齐写信和音乐的原生入口补丁，再启动游戏。仅覆盖安装不会立即改动正在运行的游戏。角色旁应显示“写信”和“音乐”小组件；这里指游戏内桌面入口，不是 Windows 桌面快捷方式。
6. 关闭管理窗口或最小化会继续在托盘运行；托盘“退出”会立即收起管理窗口，随后清理后台。等待退出完成再重新启动。
7. “停用服务”用于恢复游戏客户端的本地接入补丁，不是关闭管理软件。先退出游戏，再点停用并等待结果。备份校验失败时不要强行覆盖或删除备份，应反馈错误。
8. Steam 验证文件或游戏更新后可能需要重新启用服务；若提示不兼容，不要手工套用其他版本的备份。
9. 游戏放在映射网络盘时，请普通方式打开 OliviaSoul，不要手动“以管理员身份运行”。盘符需在当前用户会话中可见；网络断开时不能正常读取媒体或修改客户端。
10. 若默认端口 27149 已被别的程序占用，程序会自动改用下一个空闲端口（例如 27150），并把新端口写进设置。此时游戏端补丁里记录的仍是旧端口，游戏会连不上本机服务。请打开“客户端与桌面”，按提示点一次“重打补丁（同步端口）”（按钮会自动出现，状态栏也会写明哪两个端口对不上），完成后再启动游戏。若你更希望回到原端口，也可以先在“服务端口”里改成想要的空闲端口，再点该按钮。
11. 【实验性】播放自己导入的作品时，游戏背景音会让位（氛围音暂停），停止播放后恢复。做法是调用游戏自己的「氛围音挂起 / 恢复」接口，不修改任何播放路径；取不到该接口时会静默跳过（表现只是不让位，不影响播放）。如果你发现停止播放后背景音没有恢复，请在“客户端与桌面”点一次“停用服务”再重新启用，并把现象反馈给我们。

四、AI 模型配置
1. 打开“AI 模型”，在“远程兼容 API”的「选择模型」下拉里挑一个，选哪个就用哪个：
   · deepseek-flash（DeepSeek 官方，快、省，本版默认）
   · deepseek-v4-pro（DeepSeek 官方，更强，适合写回信）
   · glm-5.3-flash / glm-5.3-flashx / glm-5.3（智谱 GLM）
   · kimi-k3 / kimi-k2.6 / kimi-k2.7-code（Kimi 月之暗面，接口地址 https://api.moonshot.cn/v1）
   · 自定义（自己填接口地址和模型名，用于中转站、本地服务或其它厂商）
   程序不会自动替你换模型，测试或生成失败时也不会偷偷切到另一家。
   实测情况：DeepSeek 的 deepseek-flash 与 deepseek-v4-pro 都已实测可连通；智谱 GLM 三个只验证过接口地址可达，能不能用取决于你的智谱账号是否开通了该模型 —— 请自己填 Key 后点「保存并测试远程模型」确认。测不通不一定是程序问题，也可能是账号没权限、Key 不对或该模型未开放。
2. 填好对应服务商的 API Key，点“保存并测试远程模型”；测试成功后还要点“检测并设为当前模型”才真正启用。测试失败不会改动你已经保存的配置。公网地址必须用 https —— 明文 http 会让 Key 明文过网，程序会直接拒绝并提示；本机地址（127.0.0.1）与你自己局域网里的推理服务照旧可用。
3. 本支新增·API Key 只保存在本机 UserData\.cursor\secrets\model.env，并且只在“测试”和“实际生成回信 / 整理文本”时作为请求头直接发给你自己填的那个接口地址。程序不会把 Key 上传到本项目或任何第三方服务器，也不会把它写进运行日志、诊断包或导出包。本机管理界面为了预填打码输入框会从本地接口拿到 Key，而本地接口只监听 127.0.0.1，局域网和互联网都访问不到。留意：截图和反馈时别把 Key 露出来。
4. 用中转站或本地服务（Ollama、LM Studio 等）时选“自定义”，或改用“通用兼容 API（本地 / 中转）”档案填入地址与模型名。中转站/本地档案不会发送任何厂商专用参数，避免被严格接口拒绝。
5. 模型名可以直接手动填写，也可点击“查询模型列表”后选择候选。查询失败不会清空输入。详细示例与排错见同包《API配置使用说明.md》。
6. 本地服务需要自行在 Ollama、LM Studio 等程序中启动，并提供 OpenAI-compatible 接口。本程序不自动拉起或管理本地 AI 进程。
7. 示例本地地址：http://127.0.0.1:8000/v1 ，默认模型占位名为 local-model。普通启动不会从其他旧安装目录自动导入模型配置；同一安装目录升级仍会保留 UserData。若要清除当前安装目录保存的地址、模型和 API Key，请点击“重置模型配置 → 清除模型配置”并确认；它不会删除信件、数据库、曲库、媒体或名称纠错。
8. 来信、记忆、AI 导入和转写文本整理会用到当前模型。使用远程接口时，相关文字会发送到该接口；费用和可用性由用户的服务商/模型决定。
8. 播放已经生成好的官方 MP4 不需要 AI 再生成视频。

五、导入官方成品视频
玩家上传音乐分享（该分享由上游维护者提供、与本支无关；内容和可用性以分享页为准）：
https://ug.link/sycan/filemgr/share-download/?id=8c2b2c05b0ce4dd19c5e1c89e47e57e3
资源不随安装包附带。请仅使用有权使用的媒体；下载后保留原目录结构，按以下步骤扫描和导入。原曲名可能有误，纠正方法见第六节。

1. 准备已经下载完成的官方演奏 MP4，尽量保留原目录、library.json 和视频变体信息。支持识别的作品目录、分享历史目录及递归 midi_* 结构；以扫描预览结果为准。
2. 在“官方作品”选择曲库文件夹，点击“扫描预览”，查看识别出的作品数、可导入项和跳过原因，再“确认导入”。
3. 只有 MIDI、没有有效 MP4 时会提示缺少官方生成的视频，不建立空作品；损坏或不可解码的视频不能正常导入。
4. 默认引用用户选中的原目录，不自动搬家。导入后不要移动、删除或改动源视频文件名；外置盘和网络盘必须保持可访问。
5. 导入后在管理页“我的上传”和游戏曲库“我的上传”查看；如果游戏未更新，先刷新曲库并确认后端仍运行。
6. 如需迁移，在“客户端与桌面”的数据与曲目保存位置中“预览迁移”，核对目标、空间和文件数后再“确认迁移”。空间不足时先释放空间，不要反复点击。软件不会因单纯扫描就擅自移动原始文件。
7. 已迁移成功的文件会从迁移后的路径读取；来源保留。仅修改游戏默认保存路径，不等于旧作品已经迁过去。
8. 一首作品可能有三个或更多视频变体。文件数与作品数不是同一概念，三个时段视频通常仍算一首。
9. “游戏配置路径”只读显示游戏 usersettings.dat 当前值；“最后有效路径”是 OliviaSoul 在游戏设置暂时不可读时的回退。本机路径默认折叠，点击“查看本机路径”才会显示。它们属于本机运行时数据，不来自公开安装包，也不会因为卸载而改写游戏设置。

六、曲名不对时怎么纠正（重要）
导入名称来自原目录/清单/分享记录，它可能原本就标错。OliviaSoul 不会听歌识曲，不承诺自动把所有音乐识别成正确歌名。
1. 在管理页或游戏“我的上传”点击对应作品的“名称 / 时段”。
2. 展开“视频预览与时段”，听一个代表片段确认歌曲。若源视频本身就不是目录标注的歌曲，请纠正名称，不要按错误目录名强行重新绑定其他视频。
3. “保存”：保存当前显示名称。
4. “永久保存曲名”：纠正正式名称并保存内容标识，在保留用户数据且媒体内容对应时重新导入仍可沿用；不重命名原始文件，不搬动目录，不修改作品 ID 或时段绑定。
5. “恢复正式名称”：取消显示别名，回到已纠正的正式名称；没有永久纠错时才回到导入名称。要再次纠错，输入新名并再次永久保存。
6. 同一作品的三个时段视频共用一个作品名称，只改一次，不需要改三个视频文件名。文件名保持原样是正常的，不代表改名失败。
7. 旧作品首次永久保存可能提示内容匹配信息正在后台补全；名称已保存时无需反复点击。出现同步失败时按提示重试，并保留原视频和 UserData。
8. 永久纠错不是云端功能。换电脑请备份整个 UserData 和外部媒体目录；只拷 MP4 并删除原数据库/纠错记录，不能保证保留名称。

七、白天、傍晚、夜晚怎么对应
本机时间：白天 06:00–16:00；傍晚 16:00–20:00；夜晚 20:00–次日 06:00。
1. 明确标有时段的变体可自动对应；只有一个视频时可供各时段使用。
2. DEFAULT、ALT_2、ALT_3 或哈希文件名本身不证明时段。没有可靠信息时，请预览每个片段的画面，再在三个时段下拉框中选对应文件，点击保存。
3. 确认曲名可以只听一个片段；确认三种时段需要分别看画面，不需要把整首重复听三遍。
4. 当前画面不会因编辑映射立刻强制切换，下一次播放按已保存映射和本机时间选择。
5. 首次预览大视频、机械硬盘或网络盘视频可能较慢；生成/读取预览缓存时请等待，不要一边预览一边改动源文件。
6. 本支新增·时段依据复核：试听工具页的“时段依据复核”会把数据库现值与画面判定值并排显示，判定依据是每段视频抽帧算出的亮度与冷暖（偏亮偏冷=白天，很暗=夜晚，偏暖泛黄=傍晚）。两边对不上时，可以点“按画面判定重写这一首”，也可以手动指定白天/傍晚/夜晚。上游版本只写“从没判过”的曲子，一旦判完就改不了，本支修好了这一点。

八、播放、信件与记忆
1. 游戏里的暂停/停止按原逻辑结束当前演奏并回到默认壁纸，并非把画面暂停后继续保留。
2. 单独点播、未加入播单的作品播放完退出演奏；播单内按当前循环/顺序等播放模式处理下一首。
3. 写信新安装默认每日 3 封；“高级设置”可保存 0–999 的整数，0 表示当天不能写信，不是无限次数。升级保留已保存数量。重置次数不会删除旧信。
4. 写信提交后可读档案会同步；AI 回信还受模型耗时与回信最小延迟影响（默认 300 秒）。API 测试成功不代表回信立即出现。
5. “记忆”支持手动管理、.soul 导入和 AI 识别导入。.soul 是覆盖式恢复，会替换当前记忆、摘要和关联视频，导入前务必先导出备份。
6. 数据根目录：<OliviaSoul安装目录>\UserData\；数据库：database\olivia-local.sqlite；可读信件：信件往来\；设置和名称纠错记录：settings\。完整备份应包含 UserData 以及实际引用的外部视频目录。
7. 不要公开上传整份 UserData、.soul、数据库或信件档案，它们可能包含私人内容与配置。
8. 本支新增·数据备份与恢复：程序在改时段、写曲名、比对社区名单之前都会自动备份数据库。这些备份以前只能躺在目录里，现在可以在“高级设置 → 诊断 → 数据备份与恢复”里查看每份备份的内容（曲名多少首、时段设了多少首、信件几封）并一键回到某个时间点。恢复不是硬覆盖：当前数据库会先被整体留档为 before-restore-*.sqlite，随时可以再换回来；恢复属于“安排后重启生效”，不是热替换。
9. 本支新增·导出与导入（换电脑）：同一个面板里可以一键导出 zip（曲名、时段、歌词关联、信件），在新机器上“从导出包导入”即可。导出时会自动清空 API Key，也不包含任何音视频文件。这个包等同于你的隐私数据，不要随意外发。

九、Steam 第一次启动后停止（可选排障）
如果没有此问题，不需要配置额外工具。
本包包含已有的 Steam 启动衔接工具及说明，随首次启动同步到 UserData\tools\steam-launcher\。它不是自动启用的功能，不会在安装时改 Steam 启动项。
确有该问题时，先阅读该目录 README.md，完全退出 Steam，先预览配置再决定安装；调用 configure.ps1 时显式传入 -InstallDirectory 为 OliviaSoul 的实际安装目录，并使用自己账号的 userdata 数字目录。不要照抄他人账号或路径，不要丢弃已有启动参数。
修改前会备份。移动/卸载 OliviaSoul 前应先恢复该启动项；不熟悉命令时请反馈问题，不要盲目改 Steam 配置。

本支新增·游戏崩溃排查（与上面这个工具不是一回事，见“高级设置 → 诊断”）：
1. “游戏崩溃记录”直接读游戏自己写下的崩溃记录，告诉你崩在哪个模块、哪个偏移，以及是不是本程序改过的文件；面板能把结论生成一段可直接发给官方的文本，不用自己解读 dump。
2. “游戏日志”把游戏自写的日志整理成事件时间轴，崩溃现场会自动成块显示，方便看崩之前发生了什么。
3. “游戏崩溃规避”是一个开关：把 Chromium 官方针对某条已知崩溃路径的开关写进 Steam 启动项。它不改游戏任何文件，随时可以关；关闭时会精确移除该参数，你原有的启动参数（例如 --autorun）原样保留。开启前会备份 Steam 配置；关闭并确认已还原到原始状态后，那份备份会被自动删掉（Steam 把这些设置和账号信息存在同一个文件里，备份不应留在本机）。
   注意：这是【实验性功能，请谨慎使用】。经实测，这个开关在本游戏上没有效果（原因见第 6 条），开启后崩溃照旧；也不要把它当成“官方缺陷已经修好了”。
4. 同一处崩溃累计达到 3 次时，这个面板会主动提示可以试试打开开关，并显示崩溃次数、最近一次时间和崩溃位置。
5. 程序会自己判断这个参数有没有起作用：如果开关是开着的、而开启之后同一处又崩了，面板会直接显示“✗ 这个参数没能阻止崩溃”，并列出装开关的时间、之后的崩溃时间与崩溃位置。以前只能靠你自己观察，现在不用了。
6. 实测原因是参数到不了游戏的内嵌浏览器：游戏会给它自己那份 Chromium 重建一份命令行（带上它自己的 --user-data-dir、--bridge-obj-name、--enable-features=NetworkServiceInProcess2 等），从 Steam 启动项传进去的参数在这一跳就被丢掉了。所以换成其它 Chromium 启动开关同样不会有效。
7. 崩溃缺陷本身不在本程序：最早一次崩溃记录（08-19）早于本程序安装（09-01）；统计上，崩溃时刻与本程序收到请求的时刻也没有相关性。开启该开关后原本会退避一类页面回收，内存占用可能略微上升；关掉即可，不会有副作用。
