# API 配置使用说明

适用：本支 `2008.2.7-linli9-1.0.8`（程序版本 2008.2.7），2026-10-01；包含上游 R10.7 的中转 API 兼容更新。上游 linli.9 及更早的公开安装包不包含本支新增的模型选择、整理、备份与崩溃排查功能。

说明修订日期：2026-09-28。统一称为“中转站”，以用户使用的 seekai.cc 为配置示例。

## 一、安装与保留数据

- 安装包：退出游戏，并从托盘完全退出 OliviaSoul；备份原安装目录的 `UserData` 后，运行 Setup.exe，选择原安装目录覆盖升级，无需先卸载。
- 便携包：完整解压到独立、可写的目录，运行其中的 OliviaSoul.exe。不要只复制 EXE，也不要从 ZIP 内直接运行。新目录不会自动读取另一安装目录的配置和数据。
- 包内不附带个人 API Key、模型配置、信件、记忆或曲库。普通升级保留同一安装目录中的 UserData。

## 二、最快配置步骤

1. 启动 OliviaSoul，打开「AI 模型」。
2. 中转站或本地推理服务选择「通用兼容 API（本地 / 中转）」。
3. 在对应配置区填写接口地址、鉴权方式、API Key 和模型名。
4. 模型名可以手填；也可点击「查询模型列表」，再从候选中选择。查询失败不妨碍手填后测试。
5. 点击「保存并测试通用模型」。检测成功才保存这次配置；失败保留之前已保存的配置。
6. 确认顶部选择的是该档案，点击「检测并设为当前模型」。保存一个尚未启用的档案，不等于切换当前模型。

测试会实际发送一条短请求，可能消耗服务商额度。不要连续反复点击。测试成功说明本次请求能完成，不保证长文本、其他模型或后续网络状态一定正常。

## 三、中转站配置（以 seekai.cc 为例）

| 项目 | 填写方法 |
| --- | --- |
| 接口地址 | 按该站公开文档的默认地址格式，示例为 `https://seekai.cc/v1`；控制台若提供专用线路，以控制台为准 |
| 鉴权方式 | Bearer API Key |
| API Key | 从 seekai.cc 控制台创建或复制调用密钥；只填密钥本身，不加 `Bearer ` 前缀，不填网页登录密码 |
| 模型名 | 填该账户获准使用的完整模型 ID，可手填或查询后选择，不要凭商品显示名称猜测 |

也可填完整端点 `https://seekai.cc/v1/chat/completions`，程序会避免重复拼接，但不会自动补上 `/v1`。若中转站提供的地址带有自定义前缀，请保留完整前缀。不要把密钥放入地址；带查询参数、账号密码或 `#` 片段的地址不受支持。

### 这些地址分别做什么？

| 地址 | 用途 | 用户需要怎么操作 |
| --- | --- | --- |
| [seekai.cc 首页](https://seekai.cc) | 登录中转站控制台，获取接口地址、API Key 和可用模型名 | 用浏览器打开并登录 |
| `https://seekai.cc/v1` | OliviaSoul 调用模型的基础地址示例 | 填入软件的“接口地址”；控制台提供其他线路时，以控制台为准 |
| [接口使用文档](https://docs.newapi.ai/zh/docs/guide/feature-guide/user/api) | 查看接入方法的说明网页 | 需要时阅读，不填进软件的接口地址栏 |
| `https://seekai.cc/api/status` | 给程序读取的站点状态信息，浏览器里通常显示 JSON（类似代码的文字） | 不用访问、不用看懂，也不要填进软件；它不能用于调用模型 |

普通用户只需登录中转站，取得“接口地址、API Key、模型名”，按上面的步骤填写即可，无需自行搭建中转站。这里提供的是配置示例，尚未用该用户的 seekai.cc 密钥验证成功。

已有远程档案可以继续使用；自定义地址或模型时，在远程配置区启用「自定义模型与地址」。中转站优先使用通用档案，避免发送厂商专用参数。

### 可选的模型：在界面上直接选，不用自己猜 ID

「AI 模型 → 远程兼容 API」里有一个「**选择模型**」下拉，里面是已经配好的几项，**选哪个就用哪个**：

| 选项 | 接口地址 | 模型 ID | 说明 |
| --- | --- | --- | --- |
| `deepseek-flash` | `https://api.deepseek.com` | `deepseek-flash` | DeepSeek 官方，更快更省，**程序默认** |
| `deepseek-v4-pro` | `https://api.deepseek.com` | `deepseek-v4-pro` | DeepSeek 官方，能力更强，适合写回信 |
| `glm-5.3-flash` | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3-flash` | 智谱 GLM，原生多模态、便宜 |
| `glm-5.3-flashx` | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3-flashx` | 智谱 GLM，更快 |
| `glm-5.3` | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3` | 智谱 GLM 旗舰 |
| `kimi-k3` | `https://api.moonshot.cn/v1` | `kimi-k3` | Kimi 月之暗面，旗舰，1M 上下文，始终推理 |
| `kimi-k2.6` | `https://api.moonshot.cn/v1` | `kimi-k2.6` | Kimi 月之暗面，通用思考，可关闭 |
| `kimi-k2.7-code` | `https://api.moonshot.cn/v1` | `kimi-k2.7-code` | Kimi 月之暗面，代码场景，始终思考 |
| 自定义 | 你自己填 | 你自己填 | 自己的中转站或本地服务，见第四节 |

程序不会替你自动换模型，也不会在失败时偷偷切到另一家。要换随时回来改，改完点「保存并测试远程模型」，再点「检测并设为当前模型」才真正启用。

> **可用性实测情况（重要）**：上表里 **DeepSeek 的 `deepseek-flash` 与 `deepseek-v4-pro` 已用真实密钥实测可连通**；**智谱 GLM 的三个模型我们没有可用密钥，只验证了接口地址可达**（用无效 Key 请求会返回 401）。所以 GLM 到底能不能用，**需要你自己填 Key 后点「保存并测试远程模型」确认**。若返回 401/403，通常是账号未开通该模型、Key 不对或额度不足，不一定是程序问题。没把握就先在智谱控制台确认你的账号能调用哪个模型 ID，再填进来。

两个官方接口的模型 ID 都以平台实际返回为准，可在「AI 模型」页点「查询模型列表」确认。两个容易踩的坑：

- DeepSeek **没有** `deepseek-v4.1-flash` 之类的 ID，名字写错会直接 404；
- 智谱的模型 ID 是 `glm-5.3-flash` 这种形式，不是官网标题里的 `GLM-5.3-Flash`；同一系列还有 `glm-5.3-flashx`（更快）与 `glm-5.3`（旗舰），别混填。
- Kimi 的模型 ID 是 `kimi-k3` / `kimi-k2.6` / `kimi-k2.7-code`（旧的 `kimi-k2-0905-preview`、`kimi-latest`、`kimi-k2-thinking` 已下线）。Kimi 的 `temperature` 不可修改，程序不会发送它；`kimi-k3` 只认顶层 `reasoning_effort`，`kimi-k2.7-code` 始终思考且不接受 `thinking` 参数 —— 这些差异由程序按模型名自动处理。

程序只对**认得出家族**的模型附带厂商专用推理参数：DeepSeek 用 `thinking` + `reasoning_effort: high`；智谱 GLM 用 `thinking: enabled`（GLM 只接受 enabled） + `reasoning_effort: max`（智谱官方推荐值）。认不出家族的模型**一个厂商专用参数都不发**，避免被严格接口以 400 拒绝；「通用兼容 API（本地 / 中转）」档案则始终不发。

### 关于接口地址的安全性

- **公网地址必须用 `https://`**。明文 `http://` 时，你的 API Key 会作为请求头**明文经过网络**，同一网段或出口链路上的任何程序都可能抓到。程序会直接拒绝「公网 + http」的组合，并提示你改成 https。
- **本机与局域网地址不受此限制**：`http://127.0.0.1:8000/v1` 这类本机地址、以及你在局域网里自建的推理服务地址，照旧可以用明文 http —— 本地推理服务通常就是这么暴露的。
- 地址里**不能带账号密码、查询参数或 `#` 片段**：这类写法会被拒绝，避免凭据混进 URL 之后被日志或代理记录。
- **管理接口不对外来网页开放**：程序对游戏端补丁页面保留了跨域访问（它们要调 `/toy/*`），但管理接口（`/admin/*`）只认自己的来源。否则你在浏览器里打开的任意网页都能跨域读取到已保存的 API Key。

### 你的 API Key 是怎么被保护的

- **只存本机**：写在安装目录 `UserData\.cursor\secrets\model.env`，权限跟随你自己的 Windows 账号。
- **只发给你填的那一家**：仅在你点「保存并测试」、或程序实际生成回信 / 整理文本时，作为请求头直接发给你填写的接口地址。**程序不会把 Key 上传到本项目或任何第三方服务器**（本项目也没有这样的服务器）。
- **不进日志、不进诊断包、不进导出包**：「一键诊断包」内容固定、日志经过脱敏；「导出数据」会显式清空 API Key 字段。两者都不含 `.cursor\secrets`。
- **本机管理界面会拿到它**：界面需要把 Key 预填进打码输入框（你点眼睛图标可以核对），所以本地管理接口会把它返回给**本机页面**。这个接口**只监听 `127.0.0.1`（回环地址）**，局域网与互联网都访问不到；同理，任何能读到你本机文件的程序本来也能直接读 secrets 文件，这不是新增的暴露面。
- **界面默认打码**：Key 输入框是密码框，只有你手动点眼睛图标才显示明文。
- **你自己也要留意**：截图时别露出 Key，反馈问题时不要贴 Key。怀疑泄露就去服务商控制台删掉旧 Key、重建一个。

## 四、本机或局域网服务（非中转站用户）

- 类型：通用兼容 API（本地 / 中转）。
- 地址示例：`http://127.0.0.1:8000/v1`，端口以你实际启动的服务为准。
- 鉴权：按服务设置选择；未启用鉴权时选择无需鉴权。
- 模型：该服务实际加载并对外提供的模型 ID。

需要自己先启动推理服务，OliviaSoul 不会自动启动本地模型。另一台电脑上的服务不能填写 127.0.0.1，应填写从这台 Windows 电脑能够访问的地址，并确认端口与访问权限；不要把无鉴权接口直接暴露到公网。

## 五、支持范围

- 支持 Chat Completions 兼容请求、普通 JSON 正文、text/output_text 分段正文。
- 请求 `stream:false`，也能处理上游仍返回的 SSE；空增量和独立用量尾包不会清空正文。
- 最终正文与 reasoning/thinking 分开判断；只有推理、明确截断、断流或错误对象不会当作成功回复。
- HTTP 400/422 明确拒绝 `max_tokens` 时，保持同一上限，改为 `max_completion_tokens` 重试一次；不会因此切换服务商。
- 模型列表查询是可选操作，不会覆盖已经手填的模型名。

不支持直接填写 Claude Messages、Responses、Gemini 原生接口、Azure 特殊路由、自定义鉴权请求头或只接受 `stream:true` 的服务。相应厂商的模型若由中转站提供 Chat Completions 兼容端点，可以通过该端点接入；这不等于原生直连。

## 六、常见问题

| 现象 | 检查内容 |
| --- | --- |
| 查询模型失败，但已有模型名 | 直接手填模型名后保存并测试；部分服务没有开放模型列表 |
| HTTP 401 / 403 | 密钥是否正确、过期，鉴权方式是否匹配，令牌是否允许访问 |
| HTTP 404 | 地址是否缺少 `/v1` 或代理前缀，端点和模型名是否存在 |
| HTTP 400 / 422 | 模型或参数是否被上游支持，是否误填了原生协议地址 |
| HTTP 429 | 限流或额度限制；查看服务商控制台，稍后再试 |
| HTTP 5xx | 中转站或上游服务异常；查看服务状态，必要时联系中转站客服 |
| 超时、连接失败 | 服务是否启动，地址和端口是否可达，代理、网络或防火墙是否阻断 |
| 没有有效文字 / 正文未完整生成 | 服务只返回推理、正文为空、被过滤或截断；检查模型输出与上游设置 |
| 中转站提示无可用渠道 / 额度不足 | 检查账户和密钥额度、模型权限；渠道异常请联系中转站客服 |
| 保存成功，但仍使用原来的模型 | 在顶部选中对应档案，点击「检测并设为当前模型」 |

## 七、隐私与验证说明

回信、记忆处理、AI 导入和转写文本整理可能向当前接口发送相关文本；请使用可信服务。费用与数据处理规则以所用服务为准。不要在截图、日志或公开反馈中提交密钥；反馈时只提供脱敏地址、模型名、错误码及复现步骤。

本轮已通过协议模拟、安装版设置页与 PowerShell 回信链路验证，并在维护者当前配置的兼容服务上完成两条短请求验证。没有逐一实测所有商业中转站，也没有完成原生多协议接入。
