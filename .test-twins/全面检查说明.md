# 全面检查（每次更新都必须运行）

> 用法：`powershell -NoProfile -ExecutionPolicy Bypass -File .test-twins\全面检查.ps1`
> 目的：**每次更新都必须跑一遍**，覆盖单元、端到端、补丁注入、搬家与打包门禁。

## 为什么需要它

只跑单元测试会漏掉真实链路问题（历史上踩过多次）。本脚本按"从内到外"的顺序检查：

| 阶段 | 内容 | 覆盖什么 |
|---|---|---|
| 1 | **单元测试全量**（`node --test`，700+ 项） | 逻辑正确性 |
| 2 | **端到端**（真实产物 + 真实数据副本 + 真实 HTTP） | 启动、真实曲库、媒体 Range、播放、续播、游戏端点 |
| 3 | **数据库自愈**（制造陈旧 `-shm`/`-wal` → 启动） | 伴随文件移开留档、服务仍可用 |
| 4 | **补丁注入**（真实打补丁到测试游戏目录） | marker、注入符号、注入后 JS 语法 |
| 5 | **数据搬家**（真实触发） | 服务主动重启（exit 86）、备份、无 malformed |
| 6 | **打包门禁**（关键套件 + 打包脚本自检） | 发布阻断条件 |

## 关键约定（防止"新功能检测不到"）

1. **补丁检测必须自动跟随实现**：`g28-e2e-patch.ps1` 不硬编码 marker 与注入函数名，
   而是**从补丁脚本自身读取** `$patchMarker`、**扫描**所有 `OliviaSoulXxx=` 定义并逐个验证。
   → **新增注入函数会被自动纳入检查**，不会漏。
2. **新增/修改游戏端注入代码时**，必须同步：
   - `tools/patch-feapp-local.ps1` 的 `$patchMarker`（升版本号）
   - `tools/get-feapp-status.ps1` 的 `$currentMarker` + `$knownMarkers`（加历史版本字面量）
   - `desktop/client-backups.js` 的内嵌 marker 枚举
   - `desktop/feapp-revisions.js` 的 `FEAPP_REVISIONS`
   - **所有断言补丁版本/注入内容的测试**（`api.test.js`、`fe-v31-uninstall-contract.test.js` 等）
3. **新增用户可见功能时**，必须同步三处，否则会出现「源码改了、用户却看不到」：
   - `.test-twins/全面检查.ps1` 阶段 6 的 `$suites` 关键套件清单（加入该功能的测试套件）
   - 打包冒烟（最新的 `*-final-check.ps1`）：把该功能的套件加进 `$suites`；
     若功能体现在界面上，再加一条**产物检查** —— 直接检查解压后的 `app/**`。
     单元测试读的是**源码**，产物漏文件时测试仍会全绿（真实踩过）。
   - 端到端脚本（本目录 `g2x-e2e-*.mjs`），若该功能有运行期行为

   > 已实践（端口退让后的用户引导）：新增 `port-fallback-guidance` 套件（9 项，含真实占用端口的实测），

## 已知问题：测试套件存在句柄泄漏（会 hang）

- **现象**：`node --test` 不加 `--test-force-exit` 时，全量跑到最后会**挂住不退出**
  （实测卡了 12.5 分钟；日志停在最后一个通过的用例上，之后再无输出、无汇总）。
- **原因**：某个测试留下了未关闭的句柄（服务/子进程/定时器），Node 等它自然结束。
- **当前处理**：全面检查脚本统一使用 `node --test --test-force-exit`，跑完强制退出。
- **待办**：定位是哪个测试文件泄漏句柄并修掉，之后可以去掉该开关。
  - 定位方法：逐个文件跑 `node --test test/xxx.test.js`（**不加** force-exit），看哪个不退出。

## 已补上的漏洞：测试目录残留进程（曾逃过全量测试）

- **现象**：全面检查 6/6 全绿，但打包在「解压到测试目录」这一步失败 ——
  `Remove-Item` 报 `being used by another process`，随后 `tar` 报
  `Can't unlink already-existing object: Permission denied`，解压出**新旧混合**的目录，产物哈希随之改变。
- **根因**：上一次打包的真机冒烟启动了 `OliviaSoul.exe`（宿主）与 `runtime\node.exe`，
  冒烟结束后它们**没有退出**（宿主会自动重启子进程，不会自己结束）。
  下一次打包在删除测试目录前没有终止它们。
- **为什么全量测试没发现**：全面检查的端到端用的是 `E:\OliviaSoul-g28-realtest`，
  而打包脚本用的是 `E:\OliviaSoul-1.0-realtest` —— **两者不是同一个目录**，
  检查从不覆盖「打包脚本能否清理自己的测试目录」。
- **已修**：打包脚本在删除测试目录前调用 `Stop-ProcessesUnder` 终止占用进程；
  删除后若目录仍在则**直接报错退出**（不再带病继续）；脚本结束前清理本次启动的冒烟进程。
- **已加检查**：全面检查阶段 6 新增「打包脚本自检」，静态断言上述三段逻辑存在，
  防止以后被改掉。
- **通用教训**：**检查用的路径/资源，必须与实际执行路径一致**，
  否则检查通过不代表真实流程通过。

## 已补上的漏洞：批量改版本号污染文件（PowerShell 变量名大小写）

- **现象**：升级版本号后，`api.test.js` 与打包门禁出现 8 个新失败，错误形如
  `Unexpected token 'Microsoft.NET.Sdk.WindowsDesktop">'`、`Expected '[CmdletBinding()]...'`。
  被污染的文件：`OliviaSoul.csproj`（`<Version>` 里塞进了 package.json 与 package-lock.json 的全文）、
  `public/listen-naming-feedback.js`（`APP_VERSION` 里塞进了 build-release.ps1 全文）、
  `审计发布树.mjs`（内联快照同样被污染）。
- **根因**：批量改版本的 PowerShell 里写了
  ```powershell
  $new = [regex]::Replace($text, [regex]::Escape($OLD) + '(?![\d.])', $NEW)
  ```
  **PowerShell 变量名不区分大小写** —— `$new` 与 `$NEW` 是**同一个变量**。
  第一次迭代后 `$NEW` 变成了「替换结果」（整个文件内容），第二次迭代就把那段内容
  当成替换字符串插进了下一个文件的值里，逐层污染。
- **已修**：用 `git checkout` 恢复三个文件后，改用**不冲突的变量名 + 简单字符串替换**（`.Replace`）重做版本升级；
  5 个版本文件全链条确认一致，打包脚本 `-ResolvePathsOnly` 退出码 0。
- **教训（写进规范）**：
  1. **PowerShell 变量名大小写不敏感**，`$new` / `$NEW` / `$New` 是同一个变量 —— 命名必须真正区分（如 `$result` / `$targetVersion`）。
  2. **批量替换字符串优先用 `.Replace()`**，不要用 `[regex]::Replace()` 配变量替换串（替换串里 `$` 有特殊含义）。
  3. **改完必须立刻验证文件完整性**：行数是否正常、语法是否有效、关键行是否还在
     （本次若早一步检查 `csproj` 行数，就会立刻发现 29 行变成了 85 行）。
  4. **不要在循环里复用与替换串同名的变量**。
