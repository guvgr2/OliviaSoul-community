# OliviaSoul-community

给曲库里那些没有名字的歌起名，顺便把时段也判了。

> **最新版：`2008.2.7-linli9-1.2.0`**（客户端补丁 **FE v63** / WebPlayer v20）。这一版加了**歌单与收藏**（程序里能管、游戏里直接用）、**信件时间线**（游戏内回看全部来信与回信）与**信件 JSON 导入**（换电脑搬回来）、**曲库体检**、**备份可视化与清理**，以及**任务栏图标点一下收起 / 再点展开**；并修掉了「更新客户端补丁」要请求管理员权限（部分机器 UAC 会黑屏卡死）与智谱 / 豆包写回信被 4k 输出上限卡死这两个问题。下载与校验值见 [Releases](https://github.com/guvgr2/OliviaSoul-community/releases)，逐条说明见 [发布说明](repo/source/local-service/packaging/发布说明.md)。

## 能做什么

1. **自己听**：一首一首过，每首自动截 15 秒，听出来打字回车就写进库。同一首曲子重复传过的会一起命名。
2. **让别人替你听**：把「编号 + 曲名 + 3 段音频指纹」传到这个仓库，别人那边的程序算一遍指纹，对得上就自动填名。
   三段指纹全过才认，宁可留给人听也不填错。
3. **时段**：看画面判断白天/傍晚/夜晚，亮度加色温，在你库里 50 首 150 段上跑过一遍，跟已知答案全对上了。

另外还有：依赖自检（缺 WebView2 或 ffmpeg 会直接告诉你怎么补）、运行日志、程序内一键问题反馈。

## 后来又加的（g13 → 1.2.0）

> 下面按时间**从新到旧**排，最新一版 1.2.0 在最前面。

**歌单与收藏：程序里能管，游戏里能直接用。** 「曲库与作品 → 歌单与收藏」可以新建、改名、拖拽排序、从曲库批量选曲放进来、导出与导入 —— 小歌单出二维码，大歌单出 `.osfolder` 文件（**导入是替换那份歌单的内容，不是叠加**）。游戏端每首歌的「加播单」也接上了本地歌单：点一下展开下拉、勾选要放进哪些歌单，底部「＋ 新建歌单」可以当场建；**已经在歌单里的曲目会在行右上角显示「已在 N 个歌单」**。下拉第一行保留游戏原来的「加入音乐桌面」，不想建歌单也有去处。歌单弹层里的「播放这个歌单」会把这一夹按歌单顺序交给游戏播放器，不放歌单外的曲子。

**信件时间线：在游戏里回看全部来信与回信。** 入口在**我的信箱 → 打开任意一封信 → 详情头部右上角那一排按钮**，新多了一枚「时间线」。点开在游戏内弹层里按日期往下捋，左侧竖线与圆点区分「已回信 / 待回信 / 失败」，点卡片展开正文、回信与回信视频，底部「加载更早」用**游标**续拉 —— 不会再出现「翻页时新到的信把列表顶乱、同一封看两遍」。筛选（状态 / 归档 / 按人 / 搜索）全在服务端做，顶部写清「这份视图 N 封 · 全部 M 封 · 已回信 X · 待回信 Y · 失败 Z」。**不剧透**：还没到时间的回信显示「还没收到回信 —— 到时间了这里会出现。」，正文一个字节都不下发。

**信件能搬回另一台电脑了。** 「一键导出」以前界面只落一份 markdown（接口其实两种格式都支持），而时间线的「导入」只吃 json —— 等于「导出的信怎么搬回来」在游戏界面里没有出口。现在点一下会同时落 `.md`（给人看 / 直接分享）与 `.json`（换电脑后在「时间线 → 导入」里放回来），两条路径都写在提示里，其中一份失败会单独说明是哪一份。导入是两步走：先「预览」看会新增 / 跳过 / 冲突各几封，确认后才写库，**导入前自动备份一次数据库**；去重按 `letterId`，库里已有的信默认跳过，**不覆盖你本地的回信**。

**曲库体检：一次读完七类问题。** 「曲库与作品 → 曲库体检」把占位名（还没起名）、同名冲突、视频缺失、MIDI 缺失、时长异常、同款群命名不一致、疑似重复（可合并）一次列完。每类都写明「共 N 条，已列出前 M 条」，统计数字始终是全量，要看全就点「加载全部」；每条带「去修」，直接跳到对应页面。旧的「高级设置 → 诊断」里的曲库检查原封不动保留。

**备份能看见、也能删了。** 「高级设置 → 数据备份与恢复」里按类型汇总占用（手动 / 周期自动 / 改时段前 / 导入信件前），逐份列出时间、大小、类型，可以删除单份；「保留份数」可设 1~60，**改小不会立刻删** —— 先告诉你「将清理几份」，确认后才真删，调大即可撤销。防护：只接受备份目录内的文件名，当前正在用的库与「已安排恢复」的那份拒绝删除，删除时连 `-wal` / `-shm` 一起清。

**任务栏图标点一下收起、再点展开。** 点任务栏上的 OliviaSoul 图标（或窗口右上角的最小化按钮、托盘图标左键）时，窗口不再缩成屏幕左下角一小条，而是**整体滑到屏幕下方之外**；再点一次同一处按收起前的位置滑回来。两条口径：收起时**任务栏按钮一直保留**（不是旧版那种「隐藏到托盘」，那样按钮会消失反而不好找回），动画期间**只做位移、不做透明度渐变**（避免 WebView2 花屏）。托盘右键的「打开管理窗口」照旧能把它叫回来。

**「更新客户端补丁」不再请求管理员权限。** 以前的实现一上来就提权，而部分 Windows 24H2 机器上 **UAC 对话框会黑屏卡死**（点不了也退不出去，是系统已知问题，程序侧修不了）。现在**先按当前用户身份直接做**，只有真的报「拒绝访问」这类权限错误，才退到提权重试一次 —— 正常机器上根本不会弹 UAC。顺带修掉一个误报：用户取消授权时，以前会被报成「启用失败：更新后自检未通过」。

**写回信 / AI 识别不再被 4k 输出上限卡死。** 用智谱 GLM 或豆包（火山方舟）时，回信正文稍长、或一次要识别的信件往来多，会报「模型没有返回完整内容」—— 这两家的「最大回答」官方默认只有 4k token，而推理的思考链与正文**共用**这份预算，思考先吃掉一大块，正文就写不完。现在**写回信、AI 信件识别、逐字稿整理**三条路都显式给输出预算，个别中转站不认 `max_tokens` 时会自动换名重试一次。想省钱可以在 `UserData\.cursor\secrets\model.env` 里加 `MODEL_THINKING=off`，写回信就不再发思考参数（**默认 on，行为不变**）。另外模型家族表收成了唯一一份 `model-families.json`，程序端与写回信脚本读同一份 —— 以前 Kimi 三条会出现「点『保存并测试』通过、真写回信却走厂商默认」。

**几个适合日常聊天的模型预设（只加选项，不会替你换模型）。** 「AI 模型 → 远程兼容 API → 选择模型」下拉新增 MiniMax `M2-her`（角色扮演与多轮闲聊，64K 上下文）与豆包 `doubao-seed-character-260628` / `doubao-seed-character-251128` / `doubao-seed-2-0-mini-260428`（火山方舟，128K / 256K）。原有选项一个字节没改，程序也不会自动切换。**豆包要多一步**：光有 API Key 不够，必须先到方舟控制台「开通模型」，否则会报 403；接口地址填 `https://ark.cn-beijing.volces.com/api/v3`，**不要自己加 `/chat/completions`**。

**「功能太多找不到」又补了六条。** 程序端功能地图新增：怎么管游戏里的歌单、歌单怎么给别人或换机器导入、怎么回看信件时间线、导出的信件 JSON 怎么放回来、去哪儿看曲库体检、备份占多少空间怎么删，导航注释也从「15 个平铺页签收成 5 组」改成「17 个页签 / 6 组」。

**模型可以自己选了。** 「AI 模型 → 远程兼容 API」多了一个「**选择模型**」下拉：DeepSeek 的 `deepseek-flash`（默认，快、省）/ `deepseek-v4-pro`（更强），智谱 GLM 的 `glm-5.3-flash` / `glm-5.3-flashx` / `glm-5.3`，以及「自定义」（自己填接口地址与模型名，用于中转站、本地服务或其它厂商）。**选哪个就用哪个 —— 程序不会自动切换，失败也不会跨家回退。** 你填的 API Key 只存本机、只发给你自己填的那个接口，不会上传，也不进日志 / 诊断包 / 导出包。

**时段判错了，现在能改了。** 以前程序只写“从没判过”的曲子，你库里两千多首一旦判完，判错也永远改不了。现在「试听工具 → 时段依据复核」把**数据库现值**和**画面判定值**并排给你看：可以「按画面判定重写这一首」，也可以手动指定白天 / 傍晚 / 夜晚。

**数据能备份、也能恢复了。** 程序一直会自动备份数据库，但以前**没有恢复入口**，备份只能躺着。「高级设置 → 诊断 → 数据备份与恢复」可以查看每份备份里有什么（曲名多少首、时段多少首、信件几封）、一键回到某个时间点；回滚前会把当前这份也留档，随时能再换回来。另外：覆盖升级新版时自动备份旧库；一键导出 / 导入换电脑，**导出时会自动清掉 API Key**。

**游戏闪退能查了，还有一个可以试的开关。** 游戏内嵌的 Chromium 崩在一处固定位置（`libcef.dll + 0x921DA24`，读地址 0x0），**跟本工具无关**（调用栈全在游戏自己的 libcef 里）。「游戏崩溃记录」告诉你崩在哪个模块、是谁的问题，并能生成可直接上报的文本；「游戏日志」把游戏自写的日志变成事件时间轴。

「**游戏崩溃规避**」把 Chromium 官方针对这条路径的开关写进 Steam 启动项 —— **不改游戏任何文件、随时可关、关掉时精确移除参数**。但要说清楚：**这是实验性功能，请谨慎使用，实测对本游戏无效** —— 游戏会给自己那份 Chromium 重建命令行（带上它自己的 `--user-data-dir`、`--enable-features=NetworkServiceInProcess2` 等），从 Steam 启动项传进去的参数在这一跳就被丢掉，所以换其它 Chromium 开关同样不会有效。程序现在会自己判断并直接写明结论：开了开关之后同一处又崩，面板就会显示「✗ 这个参数没能阻止崩溃」，并给出装开关时间与之后的崩溃时间、位置。顺带一提，崩溃时刻与本程序收到请求的时刻在统计上**没有相关性**，最早一次崩溃（08-19）也早于本程序安装（09-01）。

**一台机器的实测记录（2026-09，可作为判断依据）**：当时那台机器**内核非分页池泄漏到 10.78 GB**、可用物理内存归零、提交内存 93%，游戏在**同一处签名**反复崩溃共 **11 次**；重启回收内存后（非分页池回到 1.03 GB、提交内存 51%）**不再崩溃**。结论：**崩溃与系统内存耗尽相关，与是否运行本程序无关**。这些指标不用装工具就能看到 —— 「高级设置 → 诊断 → 一键体检」（实验性）。如果你的机器可用内存长期接近 0、或内核非分页池明显偏高（正常应 < 1 GB），先重启并排查驱动，再怀疑程序。

**“功能太多找不到”也处理了。** 「基础设置」顶部有一张功能地图（想做什么 → 去哪一页），侧栏每个页签鼠标停上去都有说明。

## 指纹为什么不会填错

- 每首歌取 3 个位置的片段（第 20s / 80s / 140s 起各 60 秒）算量化色度指纹
- 自动命名必须**至少 2 段相似度 ≥ 0.90 且没有任何一段低于 0.70**
- 实测：同一录音 `[1, 1, 1]`；不同歌 `[0.566, 0.577, 0.568]` → 直接否决
- 指纹是单向派生数据，还原不出音频，也不含个人信息

## 技术栈

Node ESM + 原生 HTML/CSS/JS（沿用上游 `public/styles.css` 的类名与配色）+ C# WebView2 宿主。

## 构建

    cd repo/source/local-service
    npm install
    npm run build:win

需要 Node >= 22.5、.NET SDK、Inno Setup（脚本会自动下载 Node 运行时、ffmpeg 与 WebView2 引导程序）。

## 被杀软报毒怎么办

这个程序**没有代码签名证书**，而且它会启动 `node.exe`、调用 `ffmpeg`、扫描你本地的视频文件，
这些行为特征和某些恶意软件相似，所以杀软（尤其卡巴斯基）经常误报。程序本身不含恶意代码，源码全部公开可查。

**第三方检测结果（2026-10-11，版本 `2008.2.7-linli9-1.2.0`）**

也就是说：**内容层面没有恶意代码**，报毒来自“程序没有代码签名 + 会启动随包的 node/ffmpeg + 大量读写本地文件”这套行为与信誉判断。

三件事可以做：

**1. 加排除项（立刻见效）**

**其它杀软**：把程序所在的文件夹加进白名单即可。

**卡巴斯基**（21.x）要分两步，**第二步才是关键** —— 只加排除项通常拦不住它的行为检测：

1. `设置 → 威胁与排除 → 管理排除项 → 添加`：对象选「文件夹」，路径填 OliviaSoul 的安装目录（安装版通常是 `%LOCALAPPDATA%\Programs\OliviaSoul` 或自选目录，便携版就是解压出来的目录），保护组件把**所有**都勾上（尤其「系统监控 / 行为检测」）。
2. `设置 → 安全设置 → 排除项 → 受信任应用程序 → 添加`：把下面两个加进去，并勾上「不扫描网络流量」「不监控应用程序活动」
   - `<安装目录>\OliviaSoul.exe`
   - `<安装目录>\runtime\node.exe`

> 卡巴报 `PDM:Exploit.Win32.Generic`（或类似的 PDM / 行为检测条目）是**误报**：PDM 不看文件特征，只看行为 —— 而本程序会启动 `node.exe` / `ffmpeg` / `powershell` 子进程、大量读写你自己的数据目录、监听 `127.0.0.1` 端口，这些行为与某些恶意程序重叠，再加上程序**没有代码签名**（信誉分低），就会被拦。加进「受信任应用程序」后即可正常使用；如果被丢进隔离区，先在隔离区恢复，再完全退出程序重新打开。

**2. 优先用免安装版**

`Portable.zip` 比安装包少很多敏感行为（不需要自解压、不写注册表、不自动装依赖），
被误报的概率明显更低。Release 里两个都提供时，建议先用免安装版。

**3. 帮忙提交误报（一劳永逸）**

到 <https://opentip.kaspersky.com/> 上传被报的文件，选 **Report a false detection**，
说明这是开源学习项目并附上仓库地址。通过后所有卡巴用户都不会再被报。

想彻底解决只能给程序买代码签名证书（大约 $10/月起，例如 Azure Trusted Signing）——
签过名的程序不会显示"未知发布者"，信誉也会逐步建立起来。
